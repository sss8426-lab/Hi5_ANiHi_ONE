# 출석부 주말 다중 수업칸 자동 인식 및 월별 재배치

기준일: 2026-09-14

## 문제

업로드된 출석부 원본에서 토요일/일요일이 물리적으로 2~3칸을 차지하는 구조(병합 헤더 또는 반복 헤더)를
`attendance-auto.js`가 요일별로 인식하지 못하거나, 다음 달로 생성할 때 원본 월의 "날짜 번호 → 물리 열"
매핑을 그대로 재사용해 요일이 다른 새 달에는 틀린 위치에 열이 배치되던 문제를 고친다. 요일별 칸 수를
하드코딩하지 않고, 업로드된 원본을 자동 분석해 요일별 정책을 추론한다.

## 헤더 구조 인식

`dateGrid()`가 각 날짜 행을 스캔할 때 `mergeCells`를 함께 참조해 두 가지 구조를 모두 인식한다.

- **병합 헤더(`merged`)**: 앵커(왼쪽) 열에만 날짜/요일 값이 있고 나머지는 `mergeCell`로 병합됨.
- **반복 헤더(`repeated`)**: 그룹의 모든 열이 같은 날짜/요일 값을 리터럴로 반복함.

인식된 `headerMode`는 `dateColumns`(기존 구조, `{c, day, slot}`)에 함께 저장되고, 재생성 시 원본과 같은
스타일로 출력된다(병합은 병합으로, 반복은 반복으로 — 스타일을 임의로 바꾸지 않음).

## 요일별 slot 정책 추론 (`weekdaySlotPolicy`)

원본 워크북의 1~28일만 사용해 각 요일이 가진 칸 수를 다수결(최빈값, 동률이면 더 큰 값)로 추론한다.
1~28일만 쓰는 이유: 모든 달의 1~28일은 정확히 4번의 완전한 주(週)를 이루므로, 홀수 달 길이나 휴원으로
빠진 하루 때문에 특정 요일의 표본이 줄어드는 일이 없다(요일마다 항상 정확히 4개 표본). 29~31일은
정책 계산에서 제외된다.

휴원/추석 등으로 특정 토요일 하나만 칸 수가 줄어든 예외가 있어도, 나머지 3개 토요일이 다수결로 이기므로
정책은 예외에 영향받지 않는다(TYPE C 테스트로 검증).

## 대상 월 물리 열 재구성 (`targetCalendarColumns`)

다음 달을 생성할 때는 원본 월의 날짜 번호가 아니라, **대상 월의 실제 달력 + 추론된 요일 정책**으로
물리 열을 새로 만든다. 예: 원본에서 5일이 토요일(3칸)이었어도, 대상 월의 5일이 월요일이면 1칸만 갖고,
대상 월에서 실제로 토요일인 날짜들이 각각 정책만큼(예: 3칸)의 열을 갖는다.

## 열 폭 변화와 안전한 재배치 (`reshapeCalendar`)

요일 정책이 다르거나 대상 월의 활성 일수가 다르면 달력 영역의 총 물리 폭이 달라질 수 있다(늘어나거나
줄어듦). `reshapeCalendar()`가 이를 처리한다.

- 학생 정보 열(이름/학교 등, 달력보다 왼쪽)은 절대 이동하지 않는다.
- 달력 오른쪽의 보강/합계 등 꼬리 영역만 새 폭만큼 이동한다.
- `mergeCells`, `conditionalFormatting`/`dataValidation` sqref, `hyperlink`, `_xlnm.Print_Area`/
  `_xlnm.Print_Titles` 이름 정의는 다음 네 가지로 분류해 처리한다: (1) 달력보다 완전히 왼쪽 → 그대로,
  (2) 달력 전체를 가로지르는 범위(예: 제목 행 병합, 전체 폭 조건부 서식) → 끝 열이 변화량만큼 늘거나
  줄어듦, (3) 꼬리 영역에 완전히 포함 → 시작/끝 모두 이동, (4) 그 외(달력 내부에만 걸치는 알 수 없는
  구조) → 안전하게 실패시키고 한국어 오류를 반환(파일을 깨뜨리지 않음).
- 수식(`<f>`), 도형/그림, 표(`tableParts`), OLE 개체가 있는 상태에서 폭 변화가 실제로 필요하면
  안전하게 처리할 수 없다고 판단해 생성 전에 막는다.
- 새로 추가되는 열의 폭/스타일은 원본에서 **같은 요일 + 같은 slot 인덱스**를 가진 표본 열에서 그대로
  복사한다(예: "토요일 2번째 칸"은 원본의 토요일 2번째 칸 스타일을 따름).
- 업로드된 원본 파일 자체는 수정하지 않는다(항상 새 워크북을 생성).

## 학생별 slot 보존과 함께 발견/수정한 기존 버그

학생별로 어떤 요일 + 어떤 slot에 수업이 있는지는 기존 `channels[].slots[]` 추론 메커니즘을 그대로
사용한다. 이번 작업 중 이 메커니즘을 실제 다중 slot 학생으로 테스트하다가, 재배치와 무관한 기존 버그를
하나 발견해 함께 고쳤다: 다중 slot 요일(예: 토요일 3칸)의 0번 slot 열을 채울 때, 그 학생의 slot별 목록이
아니라 "이 행에서 표시가 있었던 모든 요일" 목록을 그대로 썼다. 그 결과 실제로는 토요일 2번째 칸에만
다니는 학생도 토요일 1번째 칸까지 함께 강조 표시되는 문제가 있었다. 0번 slot도 다른 slot과 동일하게
`channels[].slots[]`에서 자신의 slot 번호로만 조회하도록 통일했다(`public/data-core/work/attendance-auto.js`).

생성된 다음 달 출석부는 아직 일어나지 않은 달이므로 실제 출석 값(1/0)을 쓰지 않는다. 대신 그 학생의
수업 요일/slot에 해당하는 열만 배경색(하이라이트 fill)을 다르게 칠해, 교사가 체크하기 쉽게 표시만
해 둔다. 이번 회귀 테스트도 셀 텍스트가 아니라 셀 스타일(fill)을 검사한다.

## 테스트

`tests/helpers/attendance-multi-slot-fixture.mjs` — 실제 학생 데이터 없이 합성 워크북을 만드는
헬퍼. 병합/반복 헤더, 토/일 칸 수, 특정 날짜만 예외로 줄이는 휴원 시뮬레이션, 학생별 요일/slot 패턴
회전을 지원한다.

`tests/attendance-multi-slot-weekends.test.mjs` (5개, 모두 통과):

1. TYPE A(병합 헤더, 토 3칸/일 2칸, 2026-09 → 2026-10): 소스 인식, 정책 추론(`{0:2,1:1,...,6:3}`),
   대상 월 실제 요일 기준 재배치(10/3 토=3칸, 10/4 일=2칸, 10/5 월=1칸), 병합 스타일 유지, 재인식 라운드트립.
2. TYPE B(반복 헤더, 토 3칸/일 1칸): 모든 열이 리터럴 값을 갖고 병합이 생기지 않음을 확인.
3. TYPE C(휴원 예외): 토요일 하나만 1칸이어도 정책은 3칸 유지, 대상 월 모든 토요일에 3칸 적용.
4. 학생별 slot 보존: 토요일 slot 0/1/2, 일요일 slot 0 학생 각각이 재배치 후에도 정확히 자기 slot에만
   하이라이트되는지 fill 기준으로 검증(위 버그 수정으로 통과).
5. 폭이 줄어드는 케이스: 2026-08(31일, 마지막 사흘이 토/일/월이라 폭이 최대)을 소스로, 2027-02(28일,
   이론상 최소 폭)로 생성해 실제 축소·재인식을 검증. (참고: 1~28일의 요일 분포는 모든 달에서 동일하므로,
   달의 실제 폭 차이는 29~31일 존재 여부와 그 요일에서만 나온다 — 아무 두 달 쌍이나 축소를 보장하지 않아,
   이 조합을 의도적으로 골랐다.)

기존 출석부 테스트 22개(`attendance-auto.test.mjs`, `attendance-template.test.mjs`,
`attendance-controls.test.mjs`)도 모두 그대로 통과한다.

## 범위

이번 작업은 출석부 자동생성 기능(`public/data-core/work/attendance-auto.js`,
`public/data-core/work/attendance-template.js`, 관련 테스트)만 수정했다. 자료보관함, 꿈이음, 블로그,
인스타, 입시, 상담용, 공모전, OpenAI 연동 등 다른 기능은 건드리지 않았다. 새 UI 컨트롤은 추가하지 않았다
— 업로드 → 월 선택 → 생성 → 미리보기 → 다운로드/인쇄 흐름은 그대로다.
