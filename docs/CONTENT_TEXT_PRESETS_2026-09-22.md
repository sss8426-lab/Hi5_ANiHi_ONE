# 블로그·인스타 공통 문구 세트

## 구현 범위

- 공통 카탈로그와 동일 UI를 두 채널에 적용했다. 글/이미지 방향 아래 해시태그와 마지막 문구를 두 열로 유지한다.
- 열마다 기본 2개, 즐겨찾기/사용 횟수 우선 정렬, 전체 보기 이름 검색/분류, 새 저장, 수정, 복제, 즐겨찾기, 삭제, 복원을 제공한다.
- 불러오기는 해당 입력만 교체한다. 원본 프리셋을 자동 수정하지 않으며 선택 후 편집은 `수정됨`으로 표시한다.
- `현재 값을 기본값으로 저장`은 기존 기본 문자열 저장이다. 프리셋과 독립적이다.
- `현재 결과에 적용`은 블로그의 별도 하단/태그/연락처 필드만 변경한다. 인스타는 저장된 managed-tail 경계만 교체한다. 사용자가 경계를 바꾼 경우 조용히 본문을 삭제하지 않는다. 경계 없는 과거 글은 확인 후 끝에 추가한다.

## 범위·승인 정보

- 실제 campusId에 지역을 연결한다: 부천 두 본원=부천, 범박=범박동, 원종=원종동, 중동=부천중동, 옥길=옥길동, 광진=광진구, 울산=울산송정, 안산=안산, 파주=파주.
- 기존 캠퍼스 원본명과 로고 표시명은 수정하지 않는다. 두 부천 본원은 서로 다른 실제 ID다.
- 부천 애니/디자인 본원의 기존 승인된 캠퍼스 정체성만 초기 브랜드로 사용한다. 다른 캠퍼스의 브랜드·교육 과정은 추측하지 않는다.
- 캠퍼스 관리자는 `캠퍼스 추천 설정`에서 실제 브랜드, 학원명, 운영 과정, 확인된 연락처를 저장할 수 있다. 이 설정도 현재 campus/channel 범위에 저장한다. 두 브랜드 설정 시 게시물 브랜드 선택이 필요하다.
- 미확인 과정은 확인 필요 상태, 미확인 브랜드는 변수 없는 공통 문구만 사용 가능하다. 모든 캠퍼스에 임의 브랜드/부천 태그를 넣지 않는다.
- 부평 세트는 해당 부천 본원에만 제공한다. 실제 캠퍼스 연락처/명칭은 변경하지 않는다.
- 연락처 포함은 별도 선택이다. 등록값 없는 행은 생략한다. 블로그=전화/주소/https 상담 링크, 인스타=전화. 임의 연락처는 넣지 않았다.
- 변수 치환은 허용된 필드만 처리한다. 미치환 변수가 남은 문구는 저장/적용/복사 전에 안내한다.
- 5/8개는 추천 편집 기준이다. 기존 저장 계약의 최대 30개/태그 80자는 초과 안내하며 임의 절단하지 않는다. 플랫폼 공식 최대치라는 의미가 아니다.

## 저장·권한·보존

- 기존 D1 `data_records`에 `content-text-presets` 보호 레코드 1개/조직/캠퍼스/채널을 사용한다. R2와 새 DB는 사용하지 않는다.
- GET은 카탈로그를 투영할 뿐 추천 레코드를 생성하지 않는다. 안정적 builtInKey에 수정본/삭제 표식을 겹친다. 카탈로그 버전 변경보다 사용자 수정/삭제가 우선이다.
- 사용자 세트는 owner, kind, 브랜드, revision, 날짜, soft-delete 상태를 보관한다. 영구 삭제 없음. 즐겨찾기는 사용자별이고 사용 횟수는 내용 없이 로컬에 보관한다.
- 동일 범위의 저장은 metadata CAS로 보호하고 세트 revision을 검증한다. 생성 requestId로 네트워크 재시도 중복 생성을 막는다.
- 일반 사용자는 자신의 세트만 관리한다. 추천/공유 세트 관리는 기존 관리자 정책을 적용한다. 남의 개인 세트는 일반 사용자에게 노출하지 않는다.
- 일반 records API를 통한 타입 위조/조회/수정/삭제는 차단한다. 권한과 origin은 서버에서 검증한다.
- 기존 content-defaults의 metadata 교체를 json_patch로 바꿔 알 수 없는 기존 메타데이터도 보존한다. 기존 프리셋 전용 구현은 현재 main에 없었다.
- 프리셋 삭제는 입력값·기본값·과거 게시물에 영향을 주지 않는다. 확정 연락처/문구는 게시물 스냅샷이다.
- API 키, AI 모델, 원본 파일/로고/이미지 규격, 계정/캠퍼스 권한, 달력/출석부/자료실 기능은 변경하지 않았다.

- `scripts/check-instagram-carousel-browser.mjs`: 기존 1/5/10장 생성/저장/다운로드, 7종 이미지 입력, AI 실패 복구, 원본 보호, 하단 교체/저장/다시 열기 회귀. 제공자 응답은 합성 mock이며 유료 AI 실제 호출은 하지 않는다.
- 모든 테스트 쓰기는 격리된 합성 데이터다. `--preview URL`은 배포 정적 자산의 해시만 실제 URL과 비교하며 운영 DB에 테스트 세트를 남기지 않는다.
- 전체 lint에는 기존 타 모듈 오류가 남아 있다. 이번 신규 모듈 및 변경 핵심 파일의 lint, 타입 검사, 빌드, 관련 테스트는 별도 검증한다.

## 운영 시 확인 필요

기존 승인 정보에 없는 캠퍼스 브랜드·과정·전화·주소는 자동 추정/등록하지 않았다.
해당 값은 실제 운영 정보를 가진 관리자가 화면에서 확인하여 저장해야 한다.
외부 AI 키/새 저장소/결제 설정 변경은 필요 없다. 이번 기능은 텍스트 설정만 저장한다.
