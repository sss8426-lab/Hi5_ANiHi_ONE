## 실제 발견한 제품 오류 (모두 재현·수정·재검증 완료)

사용자가 지정한 실제 출석부 5개(파일-1~5로 익명화, 파일명·경로·학생 정보는 어디에도 기록하지 않음)를 읽기 전용으로 검증하는 과정에서 4건의 실제 제품 오류를 찾아 최소 범위로 고쳤다.

1. **날짜 인식이 "31일 칸이 반드시 있어야 한다"고 잘못 요구함** (`attendance-auto.js`의 `dateGrid`)
   실제 30일짜리 달(9월 등)을 물리적으로 딱 30칸만 가진 양식(여분의 31일 칸이 없는 구조)이 인식 실패했다. 28일 이상이면 이미 유효한 달력 경계라는 기존 로직은 맞았지만, 그 뒤에 "31일까지 도달해야 한다"는 불필요한 조건이 추가로 막고 있었다. 그 조건만 제거했다 (여분 칸을 빌려오는 기존 로직은 그대로 유지).

2. **조건부 서식 허용 목록이 "셀값=리터럴 비교" 한 종류만 인정함** (`attendance-auto.js`의 `analyzeWorkbook`)
   실제 파일에 Excel 기본 제공 "텍스트 포함/시작 문자" 조건부 서식(`containsText`/`beginsWith` 등, 한 파일에 약 120개)이 있으면 무조건 인식 실패였다. 이 규칙들은 항상 자기 자신의 고정 `text` 속성만 비교하고 다른 셀을 참조하지 않아 다음 달로 복사해도 안전하다. 허용 목록에 이 4가지 타입만 추가했다 (그 외 모든 타입은 여전히 거절).

3. **연도·월 인식 정규식이 "OO년 OO월" 정확한 형태만 인정함** (`attendance-auto.js`의 `period`)
   "2026학년도 9월"처럼 연도와 월 사이에 짧은 설명 문구가 들어간 실제 제목은 인식 실패였다. 숫자를 건너뛰지 않는 범위 안에서 짧은 비숫자 구간을 허용하도록 정규식만 완화했다.

4. **시트의 실제 사용 범위가 `<dimension>`/인쇄 영역 메타데이터보다 클 때 뒤쪽 학생이 통째로 사라짐** (`attendance-template.js`의 `areaFor`)
   일부 실제 파일은 편집 후 `<dimension>` 태그나 인쇄 영역이 재계산되지 않아, 실제로는 학생이 더 있는데도 그 메타데이터가 훨씬 작은 범위를 가리키고 있었다. 기존 코드는 이 메타데이터를 그대로 믿었기 때문에 학생 목록이 통째로 비어 인식 실패로 이어졌다. 실제 셀이 존재하는 범위가 선언된 범위보다 크면 그만큼만 넓히도록 고쳤다 (반대로 메타데이터가 실제보다 넓은 정상적인 경우 — 향후 학생을 위해 빈 행을 미리 서식만 잡아둔 양식 — 는 그대로 유지, 절대 줄이지 않음).

네 가지 모두 실제 파일로 재현 → 원인 확정 → 최소 범위 수정 → 기존 22개 합성 테스트 재통과 → 실제 파일 재검증 순서로 진행했다.

## 검증 스크립트에서 고친 문제

- `scripts/check-attendance-private-template.mjs`의 기존 검증이 "월이 바뀌어도 열/병합/인쇄영역이 완전히 그대로여야 한다"고 잘못 전제하고 있었다. 이는 요일별 칸 수 재배치라는 정상 기능과 모순된다. 달력 영역 밖(학생정보 열, 꼬리 영역)은 그대로 보존되는지, 달력 영역 안은 독립적으로 재구현한 요일 다수결 로직과 순수 달력 계산으로 검증하도록 다시 작성했다. 제목/연도/월 표시 셀은 생성 시 의도적으로 바뀌는 문서화된 예외로 별도 처리했다.
- 검증 대상 월을 하드코딩된 과거 두 달이 아니라 "원본의 실제 다음 달 + 2월 경계 + 1년 후 같은 달"로 매번 동적으로 계산하도록 바꿨다.
- 공개 출력은 성공/실패, 원본 불변 여부, 익명 시트 번호, 검증한 월, 검사 항목만 남기고 실제 셀 내용·경로·시트명은 어디에도 출력하지 않는다.

## 회귀 테스트 추가

`tests/attendance-real-world-fixes.test.mjs` (+ `tests/helpers/attendance-real-world-fixture.mjs`)에 4개 합성 fixture 기반 테스트를 새로 추가했다. 실제 파일의 날짜·이름·경로는 전혀 포함하지 않으며, 각 수정 사항의 원인만 최소로 재현한다.
