# 대학 데이터 관리 74개교 정리 및 수시 홈페이지 링크

## 범위와 보존

- 사용자 승인: 지정한 국내 74개교만 대학 데이터 관리에 남긴다. 수시/정시 입시요강은 보존한다.
- 운영 사전 조회: 원본 대학/학과/전형 3,915건 중 74개교 2,186건 유지, 나머지 1,729건 관리 화면에서 삭제 처리. 학교 수와 학과/전형 행 수는 다르다.
- 수시/정시 입시요강 3,826건은 별도 D1 레코드다. 다만 원본 대학 ID로 매핑을 다시 계산하므로 원본 대학을 물리 삭제하면 연결 검수에 영향을 준다.
- 따라서 원본 R2 JSON과 입시요강 D1 레코드는 수정하지 않는다. 학생/상담/추천/로드맵 연결도 유지한다.
- 별도 DB 없이 기존 data_records에 범위 전용 삭제 기록 한 건을 저장한다. 현재 화면의 CSS로만 숨기는 것이 아니라 새로고침/재로그인에도 유지되는 서버 상태다.

## 저장 및 API 계약

- 레코드: `admissions-management:approved-74-20260929`, 유형 `admissions-management-archive`, sourceApp `admissions`, 조직 `org-hi5-anihi`, campus 없음.
- metadata version=1, 승인 학교 목록, 원본 hash, 제외 항목의 id/name, 전체 제외 항목에 공통 적용되는 deletedAt, 생성일, 정리 사유를 기록한다. 중복 시각을 반복 저장하지 않으며 SQL 100KB 제한을 적용 전 확인한다.
- 인증된 GET `/api/data`에 `_universityManagementDeletedIds`를 응답한다. 기존 universities는 그대로다.
- ID와 이름이 모두 일치할 때만 삭제 표시를 적용한다. 예전 숫자 ID가 다른 학교에 재사용되면 숨기지 않는다.
- PUT에서는 클라이언트가 전송한 위 파생 필드를 버린다. 원본 JSON에 섞여 저장되거나 위조되지 않는다.
- 범용 records 읽기/쓰기/삭제 경로로 관리 삭제 기록을 조회/변조할 수 없다. 기존 서버 캠퍼스 권한은 그대로다.
- 관리 목록/검색/선택/상세만 필터한다. 삭제된 ID를 가리키는 옛 관리 링크는 남아 있는 첫 항목을 표시한다. 다른 서비스의 대학 목록에는 적용하지 않는다.
- 수시 상세의 홈페이지 값만 http/https 새 창 링크로 표시한다. 제어문자, 인증정보 포함 URL, javascript/data/상대 URL은 링크로 만들지 않는다. DOM textContent, `_blank`, `noopener noreferrer` 사용. 정시 표시는 변경하지 않는다.

## 승인된 운영 적용 도구

`node scripts/archive-university-management.mjs --remote-read-only`

읽기 전용 조사 후 `--apply-approved-74`로 명시적 적용한다. 적용 전 대학 데이터만 로컬 비공개 outputs에 백업하고, R2 전체 원본 및 D1 입시요강 hash를 적용 전후 비교한다. 학생/계정 자료는 파일로 백업하지 않는다.

74개교가 모두 대응되지 않거나 ID가 중복되면 중단한다. 동일 삭제 기록은 재실행해도 중복 생성하지 않는다. 기존 기록이 예상값과 다르면 자동 덮어쓰지 않는다. SQL과 backup, audit/applied 보고서는 git 제외 경로 `outputs/university-management-74`에 저장한다.

## '공개 자료에서 확인 필요' 조사

이 문구는 대학 공식자료가 없다는 뜻이 아니라 앱이 가져온 공개 데이터의 해당 필드가 비어 있다는 뜻이다. 현재 `admissions-model.js`의 공개 필드에는 학생부 반영방법/과목/학년/출결 필드가 없으며, `guideline-details.js`의 공개 상세 추출도 제한적이다. 단순 재동기화만으로 모든 칸이 채워지지는 않는다.

공식자료 대조 예: **2028학년도 홍익대학교 세종캠퍼스 미술우수자**, 2026-07-09 수정 시행계획의 인쇄 38쪽(PDF 39번째 페이지).

- 1단계 학생부교과 20%, 서류 80%; 2단계 서류 40%, 면접 60%.
- 학생부는 국어와 영어, 수학/사회/과학 중 한 교과군을 반영한다. 선택 교과군은 이수학점 합 등의 공식 조건에 따른다.
- 1학년 1학기부터 3학년 1학기까지 학년 구분 없이 반영하며 성취도를 활용한다.
- 해당 전형의 수능 최저학력기준은 없다. 따라서 정시의 국어/수학 비율을 이 수시 전형에 복사하면 안 된다.
- 출결/봉사를 별도 정량 점수로 반영하는지 여부와 서류평가 반영은 구분해야 한다. 자료만으로 '출결/봉사 전혀 미반영'이라고 단정하지 않는다.
- 시행계획은 변경 가능하며 최종 모집요강 확인이 필요하다. 2027 모집요강을 2028 값으로 사용하지 않는다.

공식 출처:
- [2028 시행계획 공지](https://www.hongik.ac.kr/kr/admission/notice-admission.do?articleNo=151353&mode=view&article.offset=0&articleLimit=10)
- [2028 시행계획 PDF, 38쪽](https://www.hongik.ac.kr/kr/admission/notice-admission.do?articleNo=151353&attachNo=90076&mode=download)
- [2027 수시 모집요강 공지](https://www.hongik.ac.kr/kr/admission/recruitment.do?articleNo=152315&mode=view)

이번에는 확인 방법과 실제 근거를 조사했으며 입시요강의 빈칸을 일괄 수정하지 않았다. 향후 보완은 학년도/캠퍼스/학과/전형별 공식 근거와 페이지, 문서 버전, 확인일을 갖춘 별도 검수 데이터로 다뤄야 한다. 사용자 승인 전 공개 동기화 원본을 덮어쓰지 않는다. 74개교 전체의 모든 전형 공식자료 검수는 미실행이다.

## 검증

- 합성 API 테스트: 74개교 약칭/캠퍼스 대응, 유사 다른 학교 제외, 기본 데이터 보존, 위조 파생 필드 차단, 비로그인 401, 범용 레코드 변조 403, 재사용 ID 보호.
- 격리 Chrome: 320/390/768/1024/1440/1920px에서 관리 제외/옛 링크, 검색/필터, 수시 새 창 링크, 정시 기존 표시, 기본 화면 회귀. 197개 확인, 브라우저 오류 0.
- 실제 운영 자료는 사전 조회와 승인된 삭제 상태 기록만 한다. 합성 브라우저 테스트에서 운영 쓰기 요청은 하지 않는다.
- 빌드/타입 검사 통과. 최종 전체 테스트/CI/운영 적용 증거는 PR 및 outputs 보고서에 기록한다.
