# 꿈이음 출결 취소·정정 알림

PR #308의 출결 등록 알림과 PR #309의 출석부 연동을 유지하면서, 같은 날 출결 취소 후 보호자에게 정정 알림을 전송한다.

## 처리 계약

1. 등록 전 기존 인증·캠퍼스·교사 반/학생 권한을 확인하고, 출결과 등록 감사로그를 FAMILY_DB에 저장한다.
2. 연결된 활성 보호자의 활성 기기에 기존 출결 알림을 전송한다.
3. 취소는 저장된 기록의 캠퍼스/학생을 기준으로 기존 학생 접근권한과 파일럿 캠퍼스 제한을 검사한다. 한국 시간 기준 오늘 기록만 허용한다.
4. `canceled_at IS NULL` 조건부 변경과 `attendance_cancel` 감사로그를 D1 atomic batch로 저장한다. 변경에 성공한 요청만 정정 알림을 전송한다. 동시 취소의 나머지는 404/409, 재취소는 404이며 알림을 반복하지 않는다.
5. 취소 후 활성 보호자 연결을 다시 조회하고, 각 기기 전송 직전에도 연결·활성 계정/구독·학생의 원래 캠퍼스·출결 상태를 재확인한다. 최초 알림 전송 중 취소되면 아직 전송하지 않은 기기의 최초 알림을 건너뛴다.
6. 알림 실패는 저장된 취소를 되돌리지 않는다. 직원 응답/화면에는 접수 건수, 실패 또는 설정 오류, 무구독/무연결을 구분한다. 일부 전송 성공 후 오류도 이미 접수된 건수를 보존한다.

새 DB/R2, 운영 데이터 이관, 파괴적 변경, 구독 키 변경은 없다. 기존 `canceled_at`과 감사로그만 사용한다.

## 보호자 문구와 호환

제목 예시: `꿈이음 · 출결 정정 (등원 취소)`

본문 예시: `출결 정정: ○○ 학생의 2026-10-09 15:02 등원 기록을 취소했습니다. 해당 기록은 유효하지 않습니다. 현재 출결은 앱에서 확인해 주세요.`

등원·하원·결석·지각·조퇴·보강 모두 원래 기록 날짜/시간과 종류를 명시한다. 취소가 다른 출결 상태를 확정한 것으로 표현하지 않는다. 기존 자유입력 메모는 정정 알림과 정정 내역에 재노출하지 않는다.

최초/정정 payload는 기존 `kind: attendance`를 유지하고 `attendanceAction: marked|canceled`, 불투명 `eventId`를 추가한다. 기존 설치된 service worker도 정정 제목/본문을 그대로 표시하며 같은 학생 notification tag를 사용해 이전 알림을 대체하고 다시 알린다. `/family/?openAttendance=...` 경로는 기존 보호자 인증과 자녀 연결 검사로 보호된다. 공지 Push의 일반 문구 정책은 유지한다.

이미 표시·읽은 OS 알림의 회수, provider/OS 전송 순서는 보장하지 못한다. 전송 직전 검사를 통과해 이미 진행 중인 최초 요청은 취소 후에도 접수/표시될 수 있다. 따라서 정정 본문을 독립적으로 이해할 수 있게 구성하고 앱의 현재 기록을 최종 기준으로 안내한다. 무조건 재전송은 추가하지 않는다(네트워크 예외라도 provider가 접수했을 수 있음).

## API와 앱의 정정 내역

- `DELETE /api/kkumeum/attendance/:id`: 기존 `{ok,id}`에 `guardians`, `push:{sent,failed,code}` 추가. `sent`는 provider 접수 기기 수이며 실제 기기 표시/보호자 열람 증거가 아니다.
- `GET /api/family/children/:studentId/attendance`: 기존 `events`는 유효 기록만 유지하고 `corrections`를 추가한다. 정정 항목은 `{id,studentId,date,status,label,time,canceledAt}`만 반환한다. 취소 메모, 직원 ID, 다른 보호자 정보는 제외한다.
- 보호자 홈 오늘 출결과 월별 출결 화면에서 `정정 · 등원 15:02 취소`처럼 중립 색상과 명확한 문구로 표시한다. Push가 꺼져 있거나 실패해도 인증 후 정정 내역을 확인할 수 있다.
- 취소한 기록은 직원 일별/월별 출결과 출결 횟수에서 제외한다. 다른 유효 기록은 유지한다.
- 성공/실패 응답은 기존 `private, no-store`. 보호자 관계를 서버에서 재검증하며 정정 내역을 브라우저 영구 저장소에 저장하지 않는다.

## 검증과 운영 적용 경계

`tests/kkumeum-attendance-correction.test.mjs`는 isolated Miniflare D1, 합성 학생/보호자, 임시 생성 키와 합성 provider로 검증한다. 실제 AES128GCM 전송 body를 독립 수신기로 복호화해 6종 최초 알림→취소→정정 문구를 대조한다. 동시/재취소, 다기기·부분 실패, 연결 해제·비활성·구독 해제, 권한·다른 자녀, KST 자정, 설정/암호화 키 오류, provider 거절·네트워크 예외·410, 무구독/무연결, 감사로그 실패 rollback, 최초 전송 중 취소, PWA 표시와 DOM 정정 구분을 검증한다.

코드·로컬 테스트·CI·미리보기 배포·main 병합·운영 배포·실제 수신은 각각 별도 상태다. 이 문서는 운영 적용이나 실제 보호자 수신 완료를 주장하지 않는다. 운영 확인은 해당 변경 commit이 production Worker에 배포된 증거를 확인한 후, 승인된 내부 합성 계정/기기로 최초 알림→취소→정정 표시→앱 정정 내역을 확인해야 한다. 기존 실제 학생의 기록을 검증 목적으로 변경하거나 전체 보호자에게 테스트 Push를 보내지 않는다.
