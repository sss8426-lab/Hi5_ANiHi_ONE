# 블로그 제작·원본 다운로드 통합 (2026-09-22)

## 범위와 보존

기존 DATA CORE 블로그 화면을 확장한다. 새로운 DB/버킷을 만들지 않는다.
원본 파일 ID/바이트/이름/캠퍼스, FAMILY, 기존 인스타 규격, API 키/모델은 변경하지 않는다.
기존 문구 프리셋과 content-defaults는 그대로 사용한다.

## 화면과 저장 계약

- 사진 선택 직후 원본 개별/일괄 다운로드. 선택 순서와 설명을 fileId로 연결한다.
- 공통 설명, 사진별 자료 종류/설명/확인 사실/제외 지시/본문 사용/외부 분석 동의.
- 핵심 메시지, 독자, 포함·제외, 확인 사실, 출처, 문체와 기존 검색/홈피드/균형형.
- 양식 8종: 수업, 학생 작품, 선생님 연구작, 수상, 합격, 진로, 모집, 공간.
- 양식별 인사말·상하단 자산·정렬·여백·서체·연락처 설정을 캠퍼스별로 저장.
  metadata.blogSettings.templates의 해당 유형만 json_patch로 병합한다.
  기존 기본 문구 저장은 다른 양식 및 프리셋 메타데이터를 지우지 않는다.
- 대표/본문 편집 이미지: 사진·수업·작품·소식·정보 5종, 로고 없음/공식 로고,
  로고 위치/크기, 텍스트, 밝기/가로 위치. 블로그 내부 규격 1200x900 PNG.
  작품 종류 또는 서버 보호 분류는 전체 보존(contain), 색상 변경 없이 처리한다.
- 완성본은 stable block ID를 가진 글/사진/설명/하단/연락처/태그 배열이다.
  블록 이동·삭제·텍스트 수정·부분 AI 제안 비교·적용·되돌리기, 개별 복사를 제공한다.
- 사진 순서/본문 사용 위치/원본 연결/양식/설명/실제 게시·성과 기록을 버전과 함께 저장한다.
- 새 글, 지난 글 열기, 캠퍼스 변경 시 미저장 작업 확인. 지연된 생성 응답은 수동 수정값을 덮어쓰지 않는다.
- 저장 당시 글/연락처/태그가 스냅샷이다. 기본값 변경으로 과거 글을 수정하지 않는다.

## API

- POST `/api/data-core/content/blog/files`: 선택 ID를 현재 권한 및 검증된 원본 관계로 해석.
  최대 40개, 서버 동시 확인 3개, 요청 순서 유지. 오류는 파일별 반환.
- POST `/api/data-core/content/blog/image`: 인증된 원본 버전, 1200x900 PNG 실체/CRC/팽창 한도 검사.
  동일 소유자/원본/결과 해시 재시도는 같은 파생 파일을 반환한다.
- POST `/api/data-core/content/blog/save`: schemaVersion=1, 최대 10개 선택 사진,
  160개 블록, revision CAS, 요청 ID 멱등성. 본인/캠퍼스 관리자 정책을 서버에서 확인.
  일반 records/content API로 blogPost 버전을 우회해 교체할 수 없다.
- 기존에 저장된 연결이 삭제/철회되어도 초안은 보존하고 fileIssues를 기록한다.
  새로 위조한 연결은 저장하지 않는다. ready/published와 게시용 다운로드는 차단한다.
- POST `/api/data-core/content/blog/text-action`: 명시적 텍스트 검토 또는 단일 블록 수정.
  기존 공급자/모델/사용량 계측 사용. 이미지 재분석/재생성 없음.

## 품질과 개인정보

제목 존재/글자 수를 의미 일치 통과로 표시하던 검사를 제거했다.
결정적 검사는 빈 본문, 미치환 변수, 제외 표현, 보장 주장, 연결·동의 문제를 찾는다.
숫자는 무조건 오류가 아니라 사람 확인으로 표시한다.
의미 일치는 명시적 AI 텍스트 검토 전까지 미검사다. 결과에는 blockId/상태/이유가 있다.
동일 내용 재검토는 세션 캐시를 사용하고 변경 시 이전 결과를 지운다.
검토 기록은 참고 정보이며 서버의 권한·파일·게시 준비 검사를 대체하지 않는다.
외부 사실/링크의 진실성이나 실제 사진과 글의 일치는 사람 확인이 필요하다.
학생/선생님 작품·성과·유형 미확인 사진은 새 블로그 흐름에서 텍스트 설명만 전달한다.
그 외에도 사진별 동의 및 기존 서버 원본 정책을 통과한 사진만 분석할 수 있다.

## 다운로드와 네이버 전달

- 원본은 현재 인증 API에서 no-store로 받아 ETag/크기 확인. 인코딩/업로드 없음.
- 한 장은 원래 파일명. 여러 장은 STORE ZIP의 `01_원래 이름` 형식.
  같은 이름의 다른 ID도 모두 포함한다. NFC/한글/공백/확장자 유지, 위험한 이름 정리.
- 게시용 ZIP은 실제 이미지 블록 순서. HTML ZIP은 상대 경로 이미지와 편집 가능한 글을 포함.
- 실패 파일을 조용히 빼지 않는다. 취소·오류는 작성 내용/저장 파일을 삭제하지 않는다.
- 메모리 한도: 한 묶음 총 96MiB, 전송은 한 장씩. 초과 시 분할/개별 다운로드 안내.
  디스크 스트리밍은 구현하지 않았으며 단일 96MiB 초과 파일도 현재 한도 밖이다.
- `다운로드 시작`까지만 표시한다. PC 저장 완료라고 단정하지 않는다.
- 네이버 자동 발행 없음. HTML/이미지 ZIP, 전체 텍스트, 블록 복사/개별 이미지가 대체 경로다.
  SmartEditor 실제 로그인 편집기의 붙여넣기/레이아웃 유지 검증은 아직 미실행이다.

## 검증 기록

- npm ci, build, tsc, 관련 API/브라우저 문법 검사.
- 관련 API/회귀 테스트 19개 통과: 블로그 3, OpenAI 계약 6, 홈피드 UI 7, 레이아웃 3.
- 격리 D1/R2에서 JPEG/PNG 원본 1/5/10장 SHA-256 및 ZIP 순서/동명 파일 검증.
- 비로그인/다른 캠퍼스/다른 사용자/삭제/누락/버전 충돌/취소/위조 경로 차단.
- 이미지 중복 재시도, PNG 크기, 원본 해시 보존, 파생 파일 원본 소실 검증.
- 브라우저: 30회 캠퍼스 전환, 6가지 글 유형, 실제 격리 API 저장과 재열기,
  실제 Canvas/PNG 저장, ZIP 다운로드, 부분 수정·되돌리기.
- 320/390/768/1024/1440/1920px 가로 넘침 검사 및 스크린샷.
- 다운로드 요청은 원본 확인+파일 GET만 발생. AI/분석/업로드/폴더 재조회 없음.
- 작은 합성 테스트 파일 준비 시간: 약 0.14초/0.48초/0.90초(1/5/10장).
  실제 운영 대용량/회선/AI 생성 속도 또는 교사 총 작업 시간으로 일반화하지 않는다.
- 브라우저의 생성·검토 응답은 stub이다. 실제 유료 AI 품질 및 내용 일치 정확도를 검증한 것은 아니다.
- npm ci가 기존 의존성 취약점 12개(moderate 4/high 8)를 보고했다.
  이번 변경은 의존성 버전을 바꾸지 않았으며 강제 업그레이드는 범위 밖으로 남겼다.

전체 CI 및 실제 배포 결과는 연결 PR/최종 작업 보고에 별도로 기록한다.
HTML ZIP은 실제 생성했지만 네이버 자동 삽입 및 공개 게시 성공으로 보고하지 않는다.
실제 운영/수업 장면의 AI 검수 정확도, 사람 작업 시간 80% 단축은 아직 입증하지 않았다.
