# 수상작 폴더 슬라이드

## 모음별 상세 배치 후속 변경

- 선택 폴더의 경로/관리 버튼/하위 폴더/슬라이드/썸네일 영역을 해당 모음의 폴더 선택줄 바로 아래에 배치한다.
- 재원생 모음은 위, 공개 모음은 아래에 고정한다. 공통 상세 마크업/컨트롤러를 두 번 구성하여 각자 선택 폴더, 경로, 큰 이미지, 썸네일을 동시에 유지한다.
- 미선택 모음의 상세만 숨긴다. 폴더 요청 세대/파일/이미지 캐시/현재 사진/선택 삭제 상태는 모음별로 독립적이며, 공통 업로드/삭제 확인창은 요청한 모음을 명시적으로 기억한다.
- URL의 enrolledAwardFolder/publicAwardFolder로 두 경로를 보존한다. 기존 awardFolder 단일 링크도 분류를 확인하여 해당 모음에 연다.
- 새로고침/뒤로가기에서 경로를 복구하고, 화면 이동/숨김/로그아웃 시 두 이미지 캐시를 정리한다. 서버 권한 API와 원본은 변경하지 않는다.
- 후속 로컬 검증: 관련 단위 테스트 36개 통과. 두 갤러리 동시 표시, 한쪽 조작 시 다른 쪽 사진 유지, 공개 업로드 대상, 새로고침 후 두 폴더 유지, 중복 DOM ID 없음 검증 추가.
- 격리 Worker/D1/R2 브라우저에서 8개 너비(320~1920px)의 모음 배치 및 기존 갤러리/역할별 관리 동작 통과. 운영 원본 변경 없음.
- 전체 CI와 운영 배포/접속 확인은 후속 PR 결과에서 별도 확인한다.

## 변경 범위

- 재원생/공개 수상작 폴더에 같은 큰 미리보기와 하단 썸네일 줄을 적용한다.
- 폴더 안 이미지의 첫 장을 자동 표시하고, 썸네일/좌우 버튼/방향키/Home/End/수평 스와이프로 선택한다.
- 원본 비율을 유지하며 자르지 않는다. 기존 확대창과 다운로드/선택 휴지통/업로드를 유지한다.
- 두 모음 제목은 22px, 선택 폴더 제목은 24px(좁은 화면 22px)이다.
- 경로는 연한 파란 배경과 진한 파란 현재 폴더로 구분한다. 전체 이름은 title로 제공한다.

## 데이터 및 안전성

- 기존 AwardImageCache와 인증 파일 API를 재사용한다. 별도 저장소, 공개 파일 URL, DB 변경은 없다.
- 기존 썸네일 생성/저장 정책, 폴더 및 파일 관리 권한은 변경하지 않는다.
- 로딩 중 이전 그림을 제거하고, 요청/디코딩 세대 번호로 늦은 응답을 무시한다.
- 접근 거부 시 큰 미리보기와 썸네일을 비우며 다른 경로로 재시도하지 않는다.
- 폴더 제목과 파일명은 HTML로 실행하지 않는다. 빈 폴더는 큰 미리보기를 숨긴다.
- 기존 폴더당 최대 100개 파일 조회 계약은 유지한다.

## 검증

- npm ci --ignore-scripts, npm run build, npx tsc --noEmit 및 관련 JS 문법 검사 통과.
- 기존 수상작/인증 캐시/확대창 테스트 27개와 새 슬라이드 테스트 5개 통과.
- 실제 Worker와 격리 D1/R2를 사용하는 브라우저 검사에서 320/390/430/768/820/1024/1440/1920px 확인.
- 재원생/공개, 중첩 3단계, 키보드/드래그, 확대창 동기화, 다운로드 원본 바이트, 역할별 업로드/삭제/복원을 확인.
- 추가 실패/재시도/권한 거부 브라우저 시나리오는 check-award-shared-browser.mjs에 포함한다.
- 로컬 전체 회귀 실행은 Windows loopback EADDRINUSE로 중단되었다. 전체 통과 여부는 PR의 독립 CI 결과로 판정한다.
- 운영 자료를 테스트 파일로 바꾸거나 수정하지 않는다. 배포 후 인증 화면 확인은 합성 테스트와 별도로 보고한다.

검증 산출물: outputs/award-browser/report.json, awards-*.png, outputs/award-slideshow-test.log.
