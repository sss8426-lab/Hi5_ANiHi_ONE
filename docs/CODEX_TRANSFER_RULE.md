# Codex Transfer Rule

이 프로젝트에서는 다음 조건을 만족하면 설계 대화를 멈추고 Codex 구현 단계로 전환한다.

## 여기서 계속 설계할 것

- 사업 목적 정리
- 기능 우선순위
- 사용자 흐름
- 데이터 의미
- 서비스 간 관계
- 권한 정책
- 어떤 데이터를 장기적으로 축적할지
- 성공 기준

## Codex로 넘길 것

다음 중 하나 이상이면 Codex 실행 단계다.

- 저장소 여러 파일을 동시에 수정해야 함
- 실제 빌드/테스트/브라우저 검증이 필요함
- 실제 배포된 D1/R2/인증 환경에서 확인해야 함
- 기존 기능의 대규모 리팩터링/마이그레이션이 필요함
- 새로운 웹앱 화면/API/라우터를 여러 파일에 걸쳐 구현해야 함
- 로컬/클라우드 개발환경의 명령 실행과 반복 디버깅이 필요함

## 전달 방식

Codex에는 긴 대화 원문을 넘기는 것을 기본으로 하지 않는다.

다음 순서로 전달한다.

1. `AGENTS.md` 읽기
2. `docs/DATA_CORE_CURRENT_STATUS_2026-09-07.md` 읽기
3. 해당 작업 패키지 문서 읽기
4. GitHub Issue 읽기
5. 현재 main에서 브랜치 생성
6. 구현/테스트/PR

## 현재 다음 전달 패키지

`docs/CODEX_NEXT_WORK_PACKAGE.md`

목표:

- 운영환경 DATA CORE 실검증
- 블로그/인스타 공통 콘텐츠 자동화 기반 구현

Codex가 실제 운영환경에 접근하지 못하면 성공을 가정하지 말고 코드 문제와 환경 문제를 분리해 문서화한다.
