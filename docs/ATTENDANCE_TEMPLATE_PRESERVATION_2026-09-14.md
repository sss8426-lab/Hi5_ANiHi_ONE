## 내부 분석

- 표시된 모든 sheet에서 이름 header와 날짜 1~28 이상의 순서를 탐지한다. 29~31은 원래 존재하는 빈 날짜 셀만 재사용한다. 여러 시트를 한 번에 생성하고 비대상/숨김 시트는 원본 그대로 둔다.
- 날짜 반복 열은 독립 슬롯으로 보존하며 합치거나 새 열을 만들지 않는다. 날짜별 기존 슬롯 수를 유지하며 새 달의 요일별 슬롯 수에 맞춰 전체 열을 재배열하지 않는다.
- 날짜 주변 요일, 숫자 날짜/Excel 날짜, 제목/분리된 연도·월/파일명으로 원본 월을 검증한다. 서로 다른 근거가 충돌하면 생성하지 않는다.
- 학생은 이름 문자열이 아니라 sheet + 행/블록으로 구분한다. 이름 병합 셀을 이용한 다중 행과 일반 한 행을 지원한다. 학생/빈 블록 순서와 폭·높이는 유지한다.
- 명시적 수업요일을 우선한다. 없으면 실제 날짜별 표시를 요일별로 집계한다. 같은 날짜의 여러 슬롯/행은 하루의 증거로 중복 계산하지 않는다.
- 최소 3회, 해당 요일 발생 횟수의 70% 이상 반복되는 요일을 선택한다. 한 번의 예외는 제외한다. 2회 이상이나 기준 미달인 요일이 남거나 충분한 패턴이 없으면 교사가 확인한다.
- 값이 없는 색상 양식은 반복되는 유채색 fill만 후보로 사용한다. 회색 주말 구분선/배경을 수업으로 추정하지 않는다. 표식 의미를 확정하는 AI나 임의 상태 사전은 없다.
- 확인 화면은 학생명/시트명/요일만 제공한다. 모든 불확실 학생을 확인해야 만들기가 가능하다.

## 원본 복사 및 스타일

- 기존 `attendance-template.js`의 ZIP/XML/달력/스타일/인쇄 엔진을 재사용하고 자동 분석 adapter를 추가했다. 예전 휴원·보강/행 확장 엔진 계약과 unit tests는 유지하지만 일반 UI에는 수동 양식 편집기를 노출하지 않는다.
- 원본 ZIP 엔트리를 복사하여 모든 인식 시트의 날짜/요일/제목만 변경하고 날짜 영역의 이전 실제 출결·특수 값을 지운다.
- `정`, `보강`, 월 표시, 숫자 등 이전 값을 다음 달의 출결로 복사하지 않는다. 예정일은 기존 반복 fill 또는 원본의 단순 값 일치 조건부 fill을 재사용한다. 확인 가능한 색상이 없으면 Soft Green `#E8F0EC`.
- 셀 font/border/alignment/number format과 기존 XF를 유지하고 필요한 fill만 파생한다. 같은 색상은 중복 등록하지 않는다.
- 원본 수식은 보존하며 이전 월의 캐시된 계산 결과를 지워 과거 합계를 새 합계로 보여주지 않는다. Excel 열기 시 재계산을 요청한다.
- 기존 조건부 규칙/비대상 시트/sharedStrings/관련 자산은 보존한다. 외부 연결을 실행하지 않는다.
- 31일 월/30일 월/평년·윤년 2월 모두 원본 날짜 열 수를 유지한다. 없는 날짜는 빈 셀, 다음 긴 달 생성 시 날짜 복원.
- 파일명 패턴을 보존한다: `출석부26.09_.xlsx` → `출석부26.10_.xlsx`.

## 미리보기와 인쇄

- 생성 결과만 시트 탭으로 표시한다. 화면 맞춤/실제 크기는 작은 확대 버튼으로 제공하며 좁은 화면은 가로 스크롤을 허용한다.
- 원본 A4 방향, margin, printArea, scale/fit 설정을 우선한다. 원래 한 장에 맞는 20/30명 양식은 한 장을 유지한다.
- 여러 장이 필요하면 학생 블록 단위로 나눈다. 날짜는 가로 분할하지 않으며 매 장 제목/날짜/요일을 반복한다.
- 브라우저는 sandbox iframe에서 인쇄 대화상자를 연다. 여러 시트의 방향/여백은 CSS named page로 각각 유지한다.
- 비 A4, 그림/도형/실제 머리글·바닥글이 있는 파일은 다운로드를 제공하되 웹에서 동일한 출력을 보장할 수 없어 Excel 인쇄를 안내한다.

## 검증과 한계

- 단위 테스트: 자동 인식 7개 + 단순 UI 1개 + 기존 template 9개.
- 실제 구조 기반 합성 fixture: 입시 다중행/심화 반복 날짜/동명이인/월수금+화요일 1회/화목/토요일/증거 부족.
- Chromium 1920/1440/1280/1024/820/768/430/390: 첫 화면 파일·월·생성, 결과 탭/키보드, 요일 확인, 다운로드 재열기, 인쇄 iframe, 잘못된 파일 복구, 권한별 진입, 캠퍼스 변경/이탈 검증.
- 20명/30명 한 장, 60명 세로 두 장, 2월/세로 A4 및 다중 시트 PDF 생성. 독립 PDF parser로 실제 페이지 수/A4 media box/31일 반복 확인. 내려받은 XLSX는 별도 openpyxl read-only parser로 다시 열었다.
- 실제 Excel 데스크톱 앱, 물리 프린터, 교사의 학생별 실제 정규 요일 검수는 미완료.
- 암호/매크로/전자서명/XLS, 비연속 인쇄영역, 숨긴 필수 열, 시트 보호, 모호한 날짜/월, 미지원 조건부 수식 등은 단순한 인식 실패 안내로 거절한다. 임의 좌표를 사용자에게 묻지 않는다.
- 반복 날짜 열은 원본 날짜별 슬롯 개수 그대로다. 예를 들어 새 달의 토요일 수가 달라도 수업 슬롯 열을 임의로 추가하지 않는다. 요일별 슬롯 수 재배열은 별도 양식 합의가 필요하다.
- 복잡한 number format/rich text/외부 수식의 웹 표시와 프린터 글꼴은 Excel과 완전히 같다고 보장하지 않는다. 원본 수식은 웹에서 실행하지 않는다.
- 최대 20MB/압축 해제 100MB/2,048 ZIP entries, 1,000행/128열, 시트당 학생 500명. DTD/entity/path traversal 차단 및 HTML escape 유지.
- build/typecheck/public JS/dry-run/전체 test/CI/Preview/production 최종 결과는 PR evidence와 구분한다. 기존 lint 89개와 audit 12건은 별도 기술부채이며 강제 upgrade하지 않는다.

## 실행

```sh
node --test tests/attendance-auto.test.mjs tests/attendance-controls.test.mjs tests/attendance-template.test.mjs
node scripts/check-attendance-browser.mjs
# 실제 로컬 파일 검수: ATTENDANCE_PRIVATE_SOURCE 환경변수로 경로 전달 (읽기 전용)
```

Playwright는 기존 `PLAYWRIGHT_MODULE`을 사용한다. `ATTENDANCE_ORIGIN`으로 Preview의 실제 자산 hash를 비교하고 합성 API context에서 UI를 검증한다. 운영 계정/운영 쓰기 테스트를 가장하지 않는다.
