# 캠퍼스 파일 합계와 긴 이름 표시

## 변경 범위

- 기존 `GET /api/data-core/library/folders`의 캠퍼스 카드 `fileCount`만 전체 하위 파일 합계로 변경.
- 폴더 수와 일반 하위 폴더의 직접 파일 수 계산은 유지.
- 기존 D1/R2, 업로드 방식, 캠퍼스/파일 접근 정책, 디자인 색상과 보기 방식은 유지.
- 파일 바이트, 운영 자료, 계정 및 권한 설정 변경 없음.

## 집계

캠퍼스 전체를 한 번의 그룹 집계 SQL로 읽는다. 파일 목록을 폴더별로 요청하거나
R2를 열지 않는다. 조직/캠퍼스/파일 종류/삭제 여부로 제한하고 FAMILY와 썸네일 등은 제외한다.
소유 폴더 메타데이터 및 상위 경로를 일괄 조회하여 기존 `fileFolder`와
`libraryFileReadable` 권한 검사를 통과한 그룹만 캠퍼스 합계에 반영한다.
따라서 깊이에 따른 별도 집계 제한 없이 기존에 접근 가능한 경로를 모두 포함한다.
타 캠퍼스 일반 공유 자료의 기존 읽기 예외도 유지하되 비공개/학생 자료는 합계로 노출하지 않는다.

각 요청은 no-store이며 완료된 응답을 캐시하지 않는다. 기존 이동/휴지통 처리와
복원 후 재진입 시 다시 계산한다. 백그라운드 업로드 중 루트 화면으로 돌아간 경우에도
완료 후 현재 화면을 갱신한다. 오류는 기존처럼 '확인 중'이며 0으로 위장하지 않는다.

## 이름 배치

공통 `DataCoreLibraryClient.nameMarkup`과 `.library-item-name`으로
최대 두 줄 말줄임과 전체 이름 title을 제공한다. HTML은 이스케이프한다.
폴더 이름과 개수 정보는 같은 카드의 서로 다른 행이며 개수 정보의 absolute 배치를 없앴다.
메뉴/체크박스/아이콘 영역을 확보하고 파일 격자·최근 파일의 체크박스는 미리보기 위 여백에 배치한다.
자료보관함 중첩 폴더/파일, 이동 선택창, 업로드 진행·대상, 블로그·인스타 폴더 선택에 적용한다.
운영체제 자체 파일 선택창은 앱 스타일을 변경할 수 없으므로 그대로 유지한다.

## 검증

- `tests/library-campus-counts.test.mjs`: 2+10+10=22, 더 깊은 폴더, 업로드,
  파일·폴더 이동, 휴지통, 복원, 완전 삭제, 삭제된 상위 폴더, 권한 및 단일 SQL 집계.
- 기존 자료보관함 관리/공유/기본 폴더/삭제된 경로 회귀 테스트.
- `scripts/library-count-layout-smoke.mjs`: 실제 격리 API와 합성 파일로
  320/390/768/1024/1440/1920px 격자·목록의 요소 간 겹침/넘침 및 스크린샷 검사.
- 선택, 폴더 열기, 이동 선택창, 검색/정렬, 백그라운드 업로드 후 캠퍼스 합계 갱신.
- 블로그·인스타 폴더 선택창의 좁은 화면/데스크톱 이름 표시.
- 빌드와 타입 검사 통과. 전체 lint는 기존 오류 122개로 실패하며,
  변경한 집계 파일의 기존 8개 오류가 동일함을 원본 코드와 비교했다.
  변경 JS 및 신규 테스트에는 lint 오류가 없다.

배포와 CI 상태는 PR 및 최종 보고에서 별도로 구분한다.
