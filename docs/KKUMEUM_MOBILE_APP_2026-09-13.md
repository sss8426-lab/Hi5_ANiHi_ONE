# 꿈이음 단일 모바일 UI

기준 main: `cf81c69937f7f6f26a277aa4e5ef81925ec4ebc2`. 2026-09-13 구현.

## 화면

- `/data-core/kkumeum`과 `/family/` 모두 최대 480px 단일 앱 프레임. PC에도 모바일 목록/고정 하단 메뉴를 유지한다.
- 아이소식 / 반소식 / 전체공지 / 선택전달. `?tab=`으로 새로고침, 뒤로가기, 직접 진입 지원.
- 실제 반/학생 검색, 펼치기, 이름/수정일 정렬. 가상 반을 만들지 않는다.
- 선택전달은 반 전체/개별 학생을 선택하며 기존 API 최대 200대상 한도를 따른다. 선택은 메모리에만 남고 캠퍼스 전환/새로고침 시 제거한다.
- 기존 학생/반 등록, 작품, 월간평가, 보호자 연결, 성장 통계는 모바일 하위 화면으로 보존한다. 이전 section hash도 하위 화면으로 연결한다.
- 보호자는 자체 FAMILY 인증/관계 검사를 유지한다. 작품·월간평가·알림 설정·로그아웃은 더보기에서 접근한다. 교직원 메뉴는 표시하지 않는다.
- 네트워크 실패와 빈 목록은 구별하며 재시도를 제공한다. 저장 실패 시 작성 내용 유지. 발행은 임시저장 상세에서 별도 확인한다.

## 데이터와 권한

새 테이블, migration, D1/R2 binding 없음. `family_classes`, `family_students`, `class_staff_assignments`, `announcements`, `announcement_targets`, `read_receipts` 및 기존 작품/평가/보호자 API 재사용.

추가된 API:

- `GET /api/kkumeum/announcement-capabilities?campusId=`: 실제 기존 STAFF 명시 권한 포함 캠퍼스 공지 작성 가능 여부.
- `GET /api/kkumeum/announcements/:id`: 작성자/캠퍼스 관리자/MASTER 범위 상세. 발행된 조직 공지만 조직 회원 읽기 허용. 임시 조직 공지는 MASTER 전용.
- 기존 목록에 `targets`와 실제 `readCount` 추가. 횟수가 아닌 읽은 보호자 수다. 목록은 기존 최근 100건 한도 유지.
- 교사 담당 관계가 종료되면 목록의 대상 정보와 상세 모두 현재 권한으로 다시 검사한다. 같은 목록 내 동일 대상 검사는 재사용한다.
- `DELETE /api/kkumeum/announcements/:id`: 수정 권한 있는 draft만 `archived`로 숨김. 본문/대상/파일은 보존. 이미 발행된 공지는 삭제/수정 불가. same-origin과 상태 조건 검사.

관리자는 자기 캠퍼스, 교사는 기존 배정 범위, STAFF는 기존 명시된 공지 권한만 사용한다. 화면 숨김과 별도로 API 권한을 검사한다. 보호자의 읽음 기록은 소식을 직접 열었을 때만 기존 API로 저장한다.

개인정보는 localStorage/Cache Storage에 저장하지 않는다. PWA v5는 새 정적 CSS/JS/아이콘만 캐시하고 모든 API는 network-only다.

## 연결 범위와 제한

- 일정관리: 기존 DATA CORE 캠퍼스 공통 일정 조회/등록. 학생 식별자/선택 대상을 공통 일정으로 자동 복사하지 않는다.
- 선택전달의 일정등록: 날짜가 포함된 FAMILY 일정 **안내 소식** 임시저장/발행. 예약발송·개별 일정 DB 기능을 구현한 것은 아니다.
- 현재 공지에는 첨부파일/대표이미지 연결이 없다. 공지 아이콘을 사용하며 가짜 썸네일이나 첨부를 만들지 않는다. 작품 업로드는 기존 학생 작품관리에서 계속 가능하다.
- 출석, 답변, 문의, 건의, 신청/동의서 일반 접수, 수납, 교사 배정 관리 UI는 연결된 운영 API/화면이 없어 명시적인 미연결 화면이다. 동의 정책·권한을 우회하는 새 쓰기 구조는 추가하지 않는다.
- 일반 교사가 관리자 전용 반/계정 설정을 할 수 있도록 권한을 확대하지 않는다.
- 보호자 상단 탭은 서버가 이미 허용한 소식만 유형별로 보여준다. 교직원 전체 반 목록을 보호자에게 제공하지 않는다.
