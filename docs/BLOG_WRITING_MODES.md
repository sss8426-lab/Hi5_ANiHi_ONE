# 네이버 블로그 작성 가이드·생성 프롬프트·검수

기준일: 2026-10-16. 기존 OpenAI 연결·DATA CORE 사진·저장 API를 사용한다. 게시·예약 발행·외부 계정 설정 변경은 하지 않는다.
이 문서는 사용자가 준 「SEO·AEO·GEO 작성 기준 취합본」(리드젠랩·Growth·인블로그·네이버 홈피드 해설 + 네이버·구글 공식 자료)과
「문체·진정성 편집 단계」 요청을 이 프로젝트의 블로그 생성 기능에 맞춰 정리한 것이다.

목적: 키워드만 바꾼 비슷한 글이 아니라, 독자의 검색 의도를 해결하고 실제 경험·근거로 신뢰를 만드는 글.

## 1. 실제로 반영된 곳 (코드)

| 단계 | 파일 | 하는 일 |
|---|---|---|
| 작성 기준(프롬프트) | `worker/blog-writing-modes.ts` `blogWritingGuide` | SEO·AEO·GEO 편집 강조점, 편집 설계(modePlan), 공통 금지 사항 |
| 차별화 지시 | 같은 파일 `differentiationGuide` | 같은 입력으로 만든 다른 방식 후보의 제목·소제목을 보여 주고 편집 목적이 달라야 함을 지시 |
| 생성·자동 검사 | `worker/content-openai-provider.ts` `generate` | 기존 품질 검사 + 차별화 검사, 문제가 있으면 **한 번만** 다시 쓰기, 남은 문제는 경고로 표시 |
| 차별화·사실 보존·발행 판정 | `worker/blog-editorial.ts` | `compareCandidates`, `factPreservation`, `applyStyleEdit`, `publishStatus` (AI를 부르지 않는 판정) |
| 문체·진정성 편집 | `worker/content-openai-provider.ts` `blogStyleEdit`, API `POST /api/data-core/content/blog/style-edit` | 텍스트만 보내 문체 편집 → 사실 보존 확인 → 어긋나면 편집 전 원고 유지 |
| 화면 | `public/data-core/content.js` `styleEdit`·`renderEditorial`, `content.html` `#blogEditorial` | 생성 직후 문체 편집을 자동으로 부르고, 검수 메모를 공개 원고와 분리해 표시 |

처리 순서: **생성 → 사실 검수(자동 검사·missingInfo) → 문체 편집 → 사실 보존 확인 → 사람 승인.**
발행 여부는 담당자가 정한다. 프로그램은 '발행 가능'을 자동으로 주지 않는다.

## 2. 근거의 등급 — 공식 원칙 · 연구 · 실무 해설 · 운영 가설

충돌하면 해당 플랫폼의 공식 자료를 우선한다. 업체 해설은 실무 원칙으로만 쓰고 검증된 알고리즘 규칙으로 취급하지 않는다.

- 공식 원칙(2026-10-16 Codex 작업 때 원문 확인): [네이버 서치어드바이저 콘텐츠 권장사항](https://searchadvisor.naver.com/guide/content-basic) — 일반 웹사이트 가이드이며 블로그 순위 공식이 아니다. [Google 생성형 AI 검색 가이드](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide) — 구글·자체 웹사이트 대상이며 네이버 요구사항으로 설명하지 않는다.
- 공식 원칙(이번 작업에서 원문 미확인, 충돌 시 우선 확인할 자료): [네이버 콘텐츠 작성 가이드](https://m.blog.naver.com/naver_search/224296857688), [실전편](https://m.blog.naver.com/naver_search/224305800678), [네이버 스팸 가이드](https://searchadvisor.naver.com/guide/content-abusing).
- 연구: [GEO 논문](https://arxiv.org/abs/2311.09735)(2023) — 특정 실험 결과이며 네이버 AI 브리핑 인용을 보장하지 않는다.
- 실무 해설(사용자 취합본 기준, 이번 작업에서 원문 미확인): [리드젠랩](https://blog.lead-gen.team/aeo-geo-optimization-guide-checklist), [Growth 콘텐츠 설계](https://growthmk.com/contents-geo), [Growth 개념 비교](https://growthmk.com/seo-aeo-geo-aieo), [인블로그 구글 AI 검색 해설](https://inblog.ai/ko/blog/google-ai-search-seo-guide), [인블로그 네이버 검색 해설](https://inblog.ai/ko/blog/naver-official-seo-guide), [네이버 홈피드 해설](https://dbhyeong.github.io/blog/naver-homefeed-exposure-guide-for-bloggers).
- 운영 가설: SEO·AEO·GEO 버튼 구분, 차별화 검사 기준(문장 60% 이상 같음 등), 문체 편집 단계. 노출 합격선이 아니다.

### 실무 해설에서 가져온 공통 원칙
- 리드젠랩: 실제 고객 질문 중심 기획, 중요한 답 먼저(역피라미드), 독창적 관점·실제 경험·비교 기준, 적용 방법·체크리스트.
- Growth: 배경보다 핵심 답 먼저, 주장에 근거·출처·사례 연결, 소제목과 문단만 읽어도 뜻이 통하게, 수정 전후 예시, 기존 글은 현황 점검 → 우선순위 → 재작성 → 관찰.
- 인블로그: 공식 문서의 사실과 운영자 해석 구분, 독자 만족·고유 경험 우선, SEO 기본기 유지, 수집·색인·노출 문제와 글 품질 문제 구분, 근거 없는 AI 최적화 공식 경계.
- 홈피드: 검색은 검색 의도, 홈피드는 관심·맥락. 클릭 후 기대 충족, 제목·대표이미지·본문이 같은 내용을 약속, 다음으로 궁금해할 주제 발굴.

### 채택하지 않는 주장 (공식 법칙·자동 합격선으로 만들지 않음)
키워드 밀도가 높을수록 좋다 / AEO 500~800자·GEO 2,000~4,000자 고정 / 모든 문단 200~400자 / FAQ 개수 고정 / 모든 주장에 통계 필요 /
특정 기간 안에 순위·AI 인용 발생 / llms.txt·특수 스키마가 AI 인용 필수 / 발행하면 AI가 곧바로 학습 / AI 사용·외부 링크 자체가 불이익 /
구글 요건이 네이버에 그대로 적용. 출처가 불명확한 수치·사례는 재사용하지 않는다. 읽기 쉬운 구조는 독자를 위한 편집 기준이며 AI 인용을 보장하지 않는다.

## 3. SEO·AEO·GEO = 편집 강조점 (서로 배타적인 알고리즘이 아님)

| | SEO 강조형 | AEO 강조형 | GEO 강조형 |
|---|---|---|---|
| 목표 | 검색 의도 해결: 필요한 정보를 찾고 선택하도록 | 구체적인 질문에 빠르고 명확하게 답 | 검증 가능한 근거와 적용 범위를 갖춘 분석 |
| 중심 질문 | 이 주제를 알아보는 사람은 무엇을 확인해야 하나? | 독자가 지금 묻는 질문에 바로 답했나? | 이 결론의 근거와 적용 범위는? |
| 권장 구성 | 제목 → 핵심 안내 → 선택 기준 → 방법·절차·비교 → 실제 사례 → 다음 행동 | 질문형 제목 → 직접 답 → 적용 조건·예외 → 방법·주의점 → 후속 질문 | 핵심 결론 → 판단 기준·대상 → 확인된 자료·경험 → 대안 비교·해석 → 조건·한계 → 상황별 권고 |
| 소제목 | 주제별 설명형, Q&A 반복 금지 | 실제 질문에 맞는 Q. 소제목 | 설명형, 관찰·해석·추가 확인 구분 |
| 하지 않을 것 | 키워드 반복으로 분량 늘리기 | 불확실한 걸 단정, 답 숨기기 | 근거 없이 전문용어·통계·전문가 인용 늘리기 → 근거 없으면 빼고 "추가 근거 필요" |

생성 전에 각 방식의 **편집 설계(modePlan)**를 정한다: 해결할 질문, 도입부 역할, 전개 순서, 핵심 설명 단위, 독자가 가져갈 결과. 화면의 검수 메모에 표시된다.

### 같은 주제의 구성 차이 예시 (편집 구조 예시이며 실제 학원 운영 사실이 아님)
주제: "웹툰을 처음 배우는 학생은 무엇부터 준비해야 할까?"
- SEO: 「웹툰 입문 준비: 기초 연습·장비·수업 선택 기준」 준비 항목 → 기초 연습 → 장비 선택 → 수업 비교 → 체크리스트. 결과: 전체 그림과 선택 기준.
- AEO: 「웹툰을 처음 배우려면 태블릿부터 사야 하나요?」 직접 답 → 장비가 필요한 조건 → 시작 방법 → 후속 질문. 결과: 지금 살지 판단.
- GEO: 「웹툰 입문에서 장비보다 먼저 점검할 학습 요소」 핵심 판단 → 확인된 수업·작품 자료 → 연습 방식 비교 → 해석과 한계 → 상황별 권고. 결과: 판단 근거와 적용 방법. 실제 자료가 없으면 가상의 성과·통계를 채우지 않는다.

## 4. 세 버전 차별화 검수 (`compareCandidates`)

같은 사진·요청·글 종류로 다른 방식을 이미 만들었다면 화면이 그 후보(최대 2개)를 함께 보내고, 서버가 새 후보와 비교한다.
- 지적하는 경우: 제목이 같음 / 도입부가 같음 / 본문 문장 60% 이상이 같음(제목·어미만 바꾸거나 FAQ·출처 목록만 덧붙인 유사 본문) / 소제목 수·순서·내용이 같고 질문형으로만 바뀜.
- 지적하지 않는 경우: 같은 브랜드 정보·정확한 수치·같은 실제 사례를 공유 / AEO·GEO가 모두 답을 먼저 씀. 문장이 다르면 같은 사실을 써도 통과.
- 지적되면 **한 번만** 다시 쓰고(무한 재생성 금지), 그래도 남으면 경고·발행 판정 '수정 필요'로 그대로 보여 준다. 경고를 숨기지 않는다. 차별화를 위해 사실·숫자·입장을 바꾸지 않는다.
- 세 버전은 비교·선택용 후보다. 비슷한 세 글을 같은 블로그에 연속 게시하지 않는다(이 앱은 게시를 하지 않는다).
- 한계: 단어 단위 비교라 의미가 같은데 문장을 완전히 다시 쓴 경우는 잡지 못한다. 편집 목적 충족 여부의 최종 판단은 사람이 한다.

판정은 나눠서 본다: ① 생성 성공(요청 200) ② 편집 목적 충족(차별화·modePlan) ③ 사실·출처·권한 검수(missingInfo·factChecks·사람 확인) ④ 발행 준비(아래 판정 + 기존 발행 전 체크리스트).

## 5. 공통 작성 규칙 (프롬프트에 반영)
- 기획: 중심 독자·상황·질문 하나. 실제 상담 질문·수업 문제·작품 수정 과정에서 주제 발굴. 검색량·경쟁도를 측정하지 않았다면 숫자를 만들지 않는다. 같은 질문 변형마다 글을 대량 생성하지 않는다.
- 제목: 본문이 주는 답과 일치. 지역명·과목명·브랜드 반복, 과장·공포·근거 없는 순위·허위 마감 금지.
- 도입: 핵심 답·결론 먼저, 답이 달라지는 조건을 함께. "요즘 많은 분이 관심…" 같은 일반론 금지.
- 본문: 소제목은 문단 역할을 정확히. 같은 기준으로 비교하고 장단점 함께. 중요한 정보를 이미지에만 넣지 않는다. 표·FAQ·요약은 필요할 때만.
- 근거: 실제 경험·공식 자료·운영자 해석을 구분, 출처는 주장 가까이, 숫자에는 대상·기간·단위·분모. 외부 연구를 학원 예상 성과로, 사례 하나를 모두의 효과로 바꾸지 않는다.
- 최신성: 가격·일정·모집요강은 확인 후 갱신. 날짜만 바꿔 최신 글처럼 보이게 하지 않는다.
- 상담 안내: 본문 문제 해결과 자연스럽게, 확인된 캠퍼스·경로만, 압박·링크 반복 금지.
- 학원 브랜드(HI5 미술학원·ANiHi 만화학원·HI5.ANiHi CORE): 철학을 구호로 반복하지 않고 수업의 선택·피드백·수정 과정으로 보여 준다. 합격자 수·합격률·후기·상담 대화·성적·수강 기간·작품 변화·수업료·시간표·주소·연락처·전문가 발언·연구 수치·사진·개인정보 사용 동의는 확인 없이 만들지 않는다. 입시 자료는 모집학년도·대학·학과·전형·모집인원을 구분한다.
- 홈피드: 독자가 방금 읽은 뒤 궁금해할 소재, 실제 시행착오·오해·선택 차이. 제목·대표이미지는 내용에 대한 정확한 기대. 다음처럼 해석하지 않는다: 최근 24시간 행동 = 노출 유효기간, 노출 조정 = 작성자 제재, 다양성 = 무관한 주제 섞기, CTR·체류시간 하나 = 노출 공식. 2024·2025 발표는 당시 일부 구현·실험이다.

## 6. 문체·진정성 편집 단계 (`blogStyleEdit`)

목적은 AI 탐지 점수를 낮추는 것이 아니라 기계적인 표현을 줄이고 운영자의 경험과 판단이 드러나게 하는 것이다.
- 규칙 10가지: 뻔한 인사·주제 예고 줄이기, 의미 없는 반복 요약·연결어 삭제, 추상 칭찬 → 자료에 있는 구체 행동, 소제목 수·FAQ·마무리 구조 강제 안 함, 문장·문단 길이 자연스럽게, 실제 상담 메모·수업 과정·운영자 의견 우선, 전문용어는 쉽게, 과장 대신 조건·예외, 키워드·브랜드 반복 금지, 일부러 오타·비문·억지 구어체 넣지 않기.
- 절대 금지: 없던 경험·학생 대화·후기, 미확인 수치·합격 실적·전문가 발언, 사실·조건·출처 변경, "AI 티가 없다"로 사실 검수 통과.
- 사실 보존 확인(`factPreservation`): 편집 후 새 숫자, 사라진 숫자, 새 인용문, 새 실적·후기·전문가 표현(합격·수상·후기·전문가·연구·통계·보장·1위·% 등), 새 금지 표현이 있으면 **편집을 버리고 편집 전 원고를 쓴다**. 편집 호출이 실패해도 원고는 그대로 남는다.
- 출력(화면 검수 메모): ① 편집된 원고(본문 자리) ② 삭제하거나 구체화한 표현 ③ 사실 확인이 필요한 부분 ④ 운영자가 답하면 좋은 실제 경험 질문. 자료가 부족하면 일반론을 경험담으로 꾸미지 않고 ④에 필요한 자료를 적는다.
- 사진은 다시 보내지 않는다(텍스트만). AI 사용량은 기존 블로그 항목으로 기록된다.

## 7. 발행 판정 (`publishStatus`) — 생성 성공과 별개

- **발행 보류**: missingInfo(미확인 사실·출처·권한) 또는 문체 편집의 factChecks가 있음.
- **수정 필요**: 품질·차별화 경고가 있음.
- **사람 확인 대기**: 위 문제가 없음. 사진 사용 권한·사실·제목과 본문 일치를 담당자가 확인한 뒤 발행한다.
- 공식 SEO 점수·예상 순위·AI 인용 확률은 계산하지 않는다. 기존 화면의 발행 전 체크리스트(`inspectPost`, 내용 검토 버튼)와 개인정보 확인은 그대로 쓴다.

### 발행 전 체크리스트 (통과 / 수정 필요 / 확인 불가)
- 제목이 약속한 답과 독자의 질문이 본문에서 해결되는가?
- 실제 수업·작품 근거가 있고, 사실·의견·가설을 구분했는가?
- 캠퍼스·브랜드·상담 연락처가 일치하는가?
- 수치에 학년도·전형·대상·단위·출처가 있는가? 확인일을 지어내지 않았는가?
- 학생 이름·얼굴·작품·성적·상담 내용의 사용 권한이 확인됐는가?
- 실적·성장·후기·학생 발언을 추측하거나 생성 이미지를 실제 증거로 표현하지 않았는가?
- 키워드·브랜드 반복, 근거 없는 최고·1위·합격 보장, 낚시 제목이 없는가?
- 핵심 정보가 본문 텍스트에도 있고, 출처가 주장 가까이에 있는가? 내부 메모가 본문에 없는가?

## 8. 기존 글 개선과 성과 관찰 (운영 절차, 자동화하지 않음)
1) 현황 점검: 질문·유입·정확성·독창성·상담 연결. 2) 우선순위: 실제 수요·운영 중요도가 높고 정보가 부족하거나 오래된 글부터. 3) 재작성: 답을 분명히, 중복 줄이고 사례·근거·비교·주의점 보강. 4) 관찰: 확인 가능한 유입 경로·조회·상담 결과.
- 노출 수가 없으면 CTR을 계산하지 않는다. 연동 데이터가 없으면 상담 성과를 특정 글에 귀속하지 않는다. 한 번의 급등·전후 차이로 인과를 단정하지 않는다. 관찰 기간과 바꾼 요소를 기록한다.

## 9. 플랫폼 적용 범위
네이버 블로그는 작성자가 제어하는 제목·본문·사진 설명·출처·관련 글·상담 안내에만 적용한다. robots.txt·JSON-LD·llms.txt를 네이버 블로그에 적용하라는 지침을 만들지 않는다. 일반 웹사이트용 네이버 검색 가이드를 블로그 전용 규칙으로 혼동하지 않는다. 자체 웹사이트의 크롤링·색인·메타데이터·구조화 데이터 검토는 이번 범위가 아니다.

## 10. 검증 (tests/blog-editorial.test.mjs, 가상 원고만)
- 같은 주제로 편집 목적이 다른 후보: AEO 생성 시 SEO 후보를 보내면 차별화 지시가 들어가고, 다른 결과는 통과.
- 제목만 바꾼 유사 본문: 탐지 → 정확히 한 번 재작성 → 남으면 경고·'수정 필요'.
- 근거가 부족한 GEO: "추가 근거 필요"·전문가 인용문 금지 지시, missingInfo가 있으면 '발행 보류'(생성은 성공).
- 허위 실적·후기·인용문: 문체 편집이 넣으면 편집 전 원고 유지, '발행 보류'.
- 공통 사실 공유·AEO와 GEO의 답변 우선 구조: 실패 처리하지 않음.
- 생성 성공 ≠ 발행 가능: 문제가 없어도 '사람 확인 대기'.

## 11. 남은 한계
- 다른 블로그 글을 우리 캠퍼스용으로 바꾸는 'AI로 변환하기'(convertBlogFromReference)에는 문체 편집 단계를 아직 붙이지 않았다.
- 검수 메모(편집 설계·문체 편집 내역)는 생성한 화면에서만 보이고 초안 저장에는 남지 않는다.
- 차별화·사실 보존 판정은 글자 단위 규칙이라 의미 판단을 대신하지 못한다. 실제 OpenAI 호출로 세 방식을 비교한 운영 확인은 이번 작업에서 하지 않았다(가짜 응답으로 검증).
