# 일정 등록·수정 복구 (2026-09-21)

기준 main: `ac65a585765b2f1154de65a50050d832e5b9b097`.
업무홈/상담홈 공통 달력에만 적용하며 DB migration, 기존 일정 수정,

## 원인

- 홈은 `metadata.startDate/endDate/eventType`을 전송하지만 POST는 최상위
  `startDate`만 읽었다. 정상 날짜를 입력해도 형식 오류가 발생했다.
- 기존 테스트는 최상위 날짜만 생성해 UI/API 계약 불일치를 놓쳤다.
- 공모전 마감일 감시자는 재렌더마다 새 감시자를 만들고 이전 감시자도
  다시 연결했다. 여러 번 날짜를 선택할수록 추적하지 못하는 구독이 증가했다.
- 종료일 공백은 JSON에서 생략되어 수정 시 이전 종료일이 남았다.
- 캠퍼스 계정의 신규 등록도 공유 범위를 빈 값으로 설정했다.

## 수정

POST/PATCH 모두 metadata 형식과 기존 최상위 형식을 지원한다. 중첩 값이
우선하며 누락된 수정 필드는 보존한다. 종료일은 빈 문자열로 명시하여
단일 날짜로 되돌린다. 잘못된 날짜와 날짜 뒤 추가 문자열은 서버가 거절한다.
기존 writer/owner/캠퍼스/MASTER 권한 검사는 그대로다.

달력 감시자를 두 홈에 각각 한 번 생성하고 재사용한다. 자체 마감일 DOM
변경 중에는 연결을 끊어 자기 자신을 다시 호출하지 않는다. 일정 모달의
배경 blur를 제거해 입력 중 넓은 배경의 합성 부담을 줄인다.

새 일정의 캠퍼스 선택은 로그인 membership 범위로 한정하고 첫 허용 캠퍼스를
선택한다. MASTER는 조직 공통과 전체 캠퍼스를 유지한다. 제목에 즉시 focus한다.
역전 날짜는 요청 전에 폼 안에 오류를 표시한다. 저장 중 중복 submit/닫기/입력을
차단하고 저장 실패 시 내용과 수정 상태를 유지한다.

성공 응답의 확정된 일정만 로컬 목록에 반영한다. 같은 달의 저장은 추가 GET을
기다리지 않으며 다른 달을 선택해 저장한 경우 해당 달로 이동 후 재조회한다.
월 이동은 즉시 표시하고 이전 GET을 취소하며, 취소가 늦어도 요청 번호로
오래된 응답이 현재 화면이나 저장 결과를 덮어쓰지 못하게 한다.

## 검증

- 기존 날짜/범위/권한 테스트와 실제 홈 metadata 계약 테스트 통과.
- 생성, 수정, 종료일 제거, 기존 최상위 PATCH, 잘못된 날짜, 타 캠퍼스 차단,
  거절된 요청의 기존 record 불변을 격리된 합성 데이터로 검증.
- `scripts/check-calendar-browser.mjs`: 실제 built Worker와 격리 D1/R2를 사용.
  외부 공모전 수집 응답만 대체하며 실제 운영 DB에 쓰지 않는다.

  추가 GET 0회, 오래된 월 응답 취소, 두 홈 및 MASTER 선택을 검증한다.
- 운영 key/사용자 비밀번호/실제 학생/일정으로 테스트하지 않는다.
- 전체 build/test/CI/배포 증거는 PR에 기록한다. 기존 app.js lint 오류 4개와
  신규 오류 0개를 구분한다.

## 남는 제한

기존 calendar API의 최근 100개 record 조회 후 기간 필터 구조는 이번에
변경하지 않았다. 일정량 증가 시 별도 날짜 범위 쿼리 개선이 필요하다.
불명확한 네트워크 실패 뒤 자동 쓰기 재시도는 하지 않는다. 기기별 실제 한글
IME/저속망 체감 속도는 운영 사용자 확인이 추가로 필요하다.
