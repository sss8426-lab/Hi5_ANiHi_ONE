# 관리자 메뉴 통합

## 적용 범위

- 모드 선택에서는 사이드바와 모바일 메뉴를 표시하지 않는다. 상담용/업무용 카드, 로그인 후 이동, 기존 이미지와 로고는 유지한다.
- 업무 사이드바 하단 `처음으로`를 제거하고 상담 메뉴의 홈은 `상담용 홈`으로 표시한다.
- 공통 업무 관리자 메뉴는 `운영관리`, `계정·권한 관리`만 제공한다.
- 계정 화면의 `계정 목록`에는 기존 계정 생성, 직원인증 승인, 비밀번호, 비활성화, 회원삭제, 접속 현황을 유지한다.
- `역할·권한`은 기존 membership API의 부여/해제를 사용한다. 이메일 없는 로컬 계정도 기존 서버의 userId 계약을 통해 선택할 수 있다. 역할을 새로 부여하는 것과 기존 권한 해제는 원래처럼 별도 명시적 동작이다.
- 탭은 키보드 좌우/Home/End, 뒤로가기, `?tab=roles` 링크를 지원한다. 이벤트는 최초 1회만 연결한다.
- readiness와 운영관리의 중복 진단 API 호출 화면을 운영관리 `시스템 점검`으로 통합한다. 연결 상태 새로고침과 확인 후 실제 임시 probe 진단을 유지한다.
- 운영관리/계정 화면의 헤더 링크는 `업무용 홈` 하나로 통일한다.

## 이전 링크와 권한

- `/data-core/work?view=admin` -> `/data-core/accounts?tab=roles`.
- `/data-core/readiness`, trailing slash, `.html` -> `/data-core/operations#diagnosticPanel`.
- 서버의 인증/최초 비밀번호 변경/마스터 검사 뒤에 임시 302 리디렉션을 적용한다. 기존 SPA admin 진입도 새 화면으로 이동한다.
- 현재 정책은 계정/권한/시스템 관리가 MASTER/SUPER_ADMIN 전용이다. CAMPUS_ADMIN에게 새로운 계정 관리 권한을 부여하지 않는다. 기존 자기 캠퍼스 운영 자료 접근은 유지한다.
- 비로그인 API는 401, 일반/캠퍼스 관리자 관리 API와 관리 페이지는 403을 유지한다. UI 숨김만으로 보호하지 않는다.
- DB 스키마, 계정, 역할 정책, 캠퍼스 배정, R2 원본, 비밀 설정은 변경하지 않는다.

## 검증

- `tests/admin-navigation.test.mjs`: 메뉴/단일 구현 계약, 이전 URL, 인증/권한 거부, 부여/해제, 교차 캠퍼스 보호.
- `scripts/check-admin-navigation.mjs`: 실제 Worker + 격리 Miniflare D1/R2 + Chrome. 합성 계정 로그인, 저장/새로고침/해제, 탭 키보드/히스토리, 기존 URL, 진단, 캠퍼스 차단.
- 320/390/768/1024/1440/1920px 모드 선택/계정/권한 화면: 수평 넘침 없음. 브라우저 JS 오류 0.
- 관련 테스트 18개, build, TypeScript 통과. 수정 JS/TS 파일 lint 기준선 8 -> 8, 추가 오류 0.
- 실행: `PLAYWRIGHT_MODULE`을 설치된 Playwright 모듈 경로로 지정한 뒤 `node scripts/check-admin-navigation.mjs`.
- 증거는 로컬 `outputs/admin-navigation/`에 저장한다. 합성 데이터이며 운영 계정이나 학생 자료를 변경하지 않는다.
- CI/운영 배포 및 실제 로그인 확인 결과는 PR과 최종 보고에서 구분한다.
